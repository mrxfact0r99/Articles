📁 Vulnerability Discovery

While checking the subdomains manually, I found one using an Nginx server with a reverse proxy. I performed directory brute-forcing using:

dirsearch -e conf,config,bak,backup,swp,old,db,sql,asp,aspx,aspx~,asp~,py,py~,rb,rb~,php,php~,bak,bkp,cache,cgi,conf,csv,html,inc,jar,js,json,jsp,jsp~,lock,log,rar,old,sql,sql.gz,sql.zip,sql.tar.gz,sql~,swp,swp~,tar,tar.bz2,tar.gz,txt,wadl,zip,log,xml,js,json -u a.abc.nl -w /usr/share/wordlists/nginx.txt -i 200

🔎 During fuzzing, I discovered a .file one which responded with HTTP 200 OK.

📄 This file is automatically generated by IDE and contains metadata about the backend project structure.

❗ This was sensitive information not meant to be publicly accessible — and it wasn’t restricted.
